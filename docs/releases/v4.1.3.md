# v4.1.3 会话用量记录不再写坏历史对话

本次发布修掉一个由本插件写入的会话事件引起的兼容性问题：在会丢掉 `ignorable` 标记的宿主构建上，插件写下的用量记录没有标记，而宿主读取端对「不在已知类型表内的未知事件」只在带标记时才允许跳过，于是**整份**会话日志被拒绝解释，历史对话打不开（对应 issue [#24](https://github.com/wssfk12138/dsh-damage-pulse/issues/24)）。修复包含三部分：确认宿主 `append` 是否真的转发该标记（读它的入口实现，而不是看版本号）、写入后回读确认并在标记丢失时永久停写、设置页给出提示。

## 问题

宿主的已知类型表（`packages/core/session/src/known-event-types.ts`）由仓库内 `SessionEventMap` 生成，仓库外插件的事件按定义不在表内；读取端（`packages/session/session-persistence/src/storage-contract.ts`）只在事件带持久化 `ignorable: true` 时才允许跳过。上游架构说明 `2026-08-30-retain-ignorable-external-session-events` 明确该标记是唯一的兼容机制，并且继续拒绝没有标记的未知事件。

插件写入的两处都传了 `{ ignorable: true }`，但这个标记能否落盘取决于宿主的 `Session.append`：已发布的 `@deepseek-ai/dsh-session@0.1.7-alpha.2` 与 `0.1.7-rc.2`（npm 上 latest/next 均为后者）都只转发 `sourceEventSeqs` 与 `surfaceOp`，会丢掉它——issue #24 的两位报告者分别给出了打包产物里 `append` 与 `.d.ts` 的证据，本仓库也复核了发布包。因此在这些宿主上运行过插件的用户，其会话日志里会留下没有标记的 `token-usage/record`；之后任何宿主（包括升级后的同一个宿主）读这些会话都会被整体拒绝，金额与用量一起消失。日志本身没有损坏，但当前宿主不会放松该判定，而且**版本号区分不出宿主是否转发该标记**，所以不能用版本线放行。

## 修复

- 新增 `plugins/dsh-token-monitor/src/session-records.ts`：写入前解析宿主 `@deepseek-ai/dsh-session` 的入口文件，确认 `append` 的元数据构造里存在 `ignorable` 转发才写入；入口无法解析或读取失败时一律停写。每次写入后仍回读宿主实际返回的 event，一旦发现标记丢失就永久停写并上报原因。
- 两个采集器改为只经该出口写入（`collector.ts` / `collector-core.ts` 的 `appendUsageRecord` 选项）；没有写入器时不再自行追加，避免任何调用方绕过前置检查。
- 停写后会话金额退回既有兜底路径（插件自有账本 `usage.jsonl` 与 `GET /api/token-monitor/session-costs`）；这些宿主上不再出现对话流内的单次用量行。
- 新增只读路由 `GET /api/token-monitor/host-compat`：返回写入能力、检测到的宿主版本与入口路径、以及原因；设置页在界面顶部以提示条展示原因与恢复方式。
- 环境变量 `DSH_TOKEN_MONITOR_FORCE_SESSION_RECORDS=1` 可显式放开写入（宿主实现无法读取、但已人工确认可用的场景）。

## 兼容性

- 实现里确认转发该标记的宿主（例如本仓库检出的 harness 源码、以及将来发布该转发的宿主版本）行为不变：继续写入会话用量记录，对话流内的单次用量行照常出现。
- 目前已发布的所有宿主版本都不转发该标记，因此这些环境不再写入会话用量记录，避免继续产生打不开的会话；金额仍由账本与兜底路由提供，设置页会明确说明原因。
- 本次改动同时涉及客户端（设置页提示与新路由客户端），`lib/client.js` 已按新源码重建。

## 已经写坏的会话

无标记的记录无法被当前宿主读取，插件也无法改写宿主存储。受影响会话需要在日志里给那几条 `token-usage/record` 补上 `ignorable: true` 才能恢复（见 issue #24 的说明），或先把它们移出 `sessions` 目录；本版本只保证不再产生新的这类会话。补充：`patches/README.md` 第 1 条宿主补丁只覆盖 `@deepseek-ai/dsh-session@0.1.7-alpha.2`；`0.1.7-rc.2` 需要按同样思路单独调整宿主安装树，而且会随宿主升级失效。
