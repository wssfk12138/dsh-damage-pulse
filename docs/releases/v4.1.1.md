# v4.1.1 修复 DSH 0.1.7 的单次用量行

本次发布只修正一处从早期版本沿用下来、在 DSH 0.1.7 上会让「对话流里的单次用量行完全不出现」的宿主适配问题，其余功能与 4.1.0 一致。

## 问题

插件把「单次用量行」的节点定义注册在宿主顶层的 \`conversationEvents\` 服务上，并在该服务不存在时整体跳过注册：

\`\`\`ts
const events = ctx.get('conversationEvents', false)
if (events) {
  const remove = events.register(tokenUsageNodeDefinition)
  dispose.push(ctx.slots.inject('conversation.chat.node', () => ctx.slots.register(…, UsageNodeView)))
}
\`\`\`

DSH 0.1.7 把这个注册表改名为 \`uiConversation.events\`（\`ConversationEventRegistry\`），不再提供顶层 \`conversationEvents\`，于是这段判断恒为假：节点定义与聊天席位都不注册，对话里那条「命中 / 未命中 / 输出」的每步扣费行不再出现，而且全程静默、没有任何报错可参考。

## 修复

节点定义改为优先读 \`uiConversation.events\`，旧宿主继续回退到顶层的 \`conversationEvents\`：

\`\`\`ts
const events = ctx.get('uiConversation', false)?.events ?? ctx.get('conversationEvents', false)
\`\`\`

两代宿主共用同一条注册路径，两种注册表都返回可释放的 disposer，随模块卸载一起回收。提供 \`uiConversation\` 的 \`@deepseek-ai/dsh-client-ui-conversation\` 本来就在本插件的客户端注入清单里，所以本次不新增任何客户端依赖，旧宿主的加载图与行为完全不变。

## 兼容性

- 宿主范围不变：\`0.1.0-rc.5\` 起的全部旧版、DSH Desktop \`2.0.4\`、\`0.1.5\`/\`0.1.6\` 线，并继续支持最新的 \`0.1.7-rc.2\`。
- \`package.json\` 版本 4.1.1，\`CURRENT_RELEASE_VERSION\` 同步；客户端产物仍为单文件 bundle。
- 旧宿主（提供顶层 \`conversationEvents\` 的版本）行为与 4.1.0 完全相同。
