# v4.0.8 Compatibility Update

Fixes two failures reported against the DSH 0.1.5 line. Both were reproduced from official 0.1.5 sources before any code change.

## 1. Host: session history migration failed on every session

DSH 0.1.5 changed `SessionPersistence` handles: `open(id, "read")` now returns `read()` yielding a `SessionHandleReadResult` wrapper `{ eventState, events }` instead of a bare event array.

- 0.1.5 does not expose `SessionPersistence.inspect()`, so every session took the `open()` branch and every call received the wrapper object.
- `4.0.7` passed that wrapper directly as the `events` argument of `sessionProjectionCache.coldSnapshot(meta, inheritedEventCount, events)`, so persisted `tokenCost` projections were never rebuilt. Session history had no cost to show, and the amount badge below had nothing to display.

`4.0.8` accepts both contracts: a bare event array (0.1.0-0.1.4) and the `SessionHandleReadResult` wrapper (0.1.5-alpha and newer), selecting `result.events` when present. The `coldSnapshot` arity probes, `inspect()` detection, and `sessionProjectionCache` service usage are unchanged, so older hosts keep their existing behavior.

Reproduction: a host on 0.1.5-alpha.2 with existing sessions. Every historical session failed projection rebuild, which the plugin logged per session at startup.

## 2. Client: amount badge was registered on a seat that DSH never declared

`4.0.7` registered the session amount badge on `sidebar.workspaces.sessionRow.trailing`. That seat does not exist in the official 0.1.3 or 0.1.5 `ui-workspace` slot contracts; it was only ever present in a locally patched host that added the seat at `ui-workspace/src/client/contract/slots.ts`. On an unmodified install the registration waits forever, so the badge never appeared.

`4.0.8` registers the badge on `conversation.session.header.actions`, which is declared in both 0.1.5 (`packages/client/ui-conversation/src/client/contract/slots.ts`) and rc.7 build output. The seat is a `session`-scoped list, so `SessionCostBadge` receives `sessionId` and `useSessions` from the standard slot props and needed no component change. It registers with `id: token-monitor-session-cost` and `order: -5`.

The trailing seat is kept as an optional additional registration: it appears only if a host declares it (such as the locally patched one), and `slots.inject` leaves it permanently pending otherwise. No host file is modified and no bundle rebuild of DSH is required.

The legacy bridge on `shell.overlay` is unchanged. It still injects amounts into unmodified sidebar rows and retires itself once a row carries a stable session marker or a formal seat marker, so patched hosts do not get duplicated amounts.

## Scope

- `plugins/dsh-token-monitor/src/migration.ts`: accept the 0.1.5 read-result wrapper.
- `packages/client/ui-token-monitor/src/client/index.ts`: register the official header seat; keep the optional trailing seat and the legacy bridge.
- `packages/client/ui-token-monitor/src/client/sessionCost.ts`: export `SESSION_HEADER_ACTIONS_SLOT`; document the trailing seat as patch-host only.
- `package.json`: version `4.0.8`; every `@deepseek-ai/dsh-*` peer range keeps the existing legs and adds `^0.1.5-alpha.1`.
- Tests and bundle gates updated for both contracts; README and install notes updated.

## Verification Scope

Node tests (50/50) and Vitest tests (338/338, 39 files) pass, `tsc --noEmit -p tsconfig.bundle.json` is clean, `scripts/check-standard-bundle.mjs` reports 27/27 checks (including two new gates that fail when `lib/index.js` is not rebuilt from the fixed Host source), and `git diff --check` is clean.

Confirmed against official 0.1.5 sources before changing code: `packages/session/session-persistence/src/handle.ts` declares `read(): Promise<SessionHandleReadResult>` carrying `eventState` and `events`; no `inspect()` exists anywhere in the 0.1.5 persistence sources, so every session takes the `open()` branch; `packages/client/ui-conversation/src/client/contract/slots.ts` declares `conversation.session.header.actions` as a session-scoped list; and `packages/client/ui-workspace` declares no `sessionRow` seat at all.

The real-SlotRegistry regression test loads the built `lib/client.js` against the rc.7 runtime bundle. It caught a lost `this` binding from calling `slots.register` detached from `ctx.slots`, which the fake registry in the other suite never surfaced; the call is now bound and both suites pass.

Not verified here: a live DSH 0.1.5 profile. No 0.1.5 installation was available in this environment, so session-history migration and badge rendering were not observed in a running renderer and still need confirmation on a real host.
