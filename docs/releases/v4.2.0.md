# v4.2.0 账号路由与官方 API key 路由共用同一套官方计价

本次发布让 DeepSeek 账号路由（provider id `deepseek-account`）在计费资格、默认规则、余额来源、用量查询与客户端扣费反馈上与官方 API key 路由（`deepseek-official`）同族同价。此前资格判定只认 `deepseek-official`，账号路由下的调用会落成「未计价」，悬浮卡片的用量概览查不到记录而显示「未记录」，客户端的扣费事件也被整体丢弃（既不显示「-¥」飘字，也不触发鲸鱼娘的受击/扣血动画）。

## 问题

- `resolvePricingEligibility` 只对 `provider === 'deepseek-official'` 返回价格命中，账号路由被直接判为不合格，账本记 `billingStatus: 'unpriced'`、`cost` 为 0。
- 默认计费规则没有账号供商标板；已保存的旧快照（本机 desktop profile 的 `state.json` 即只有 `deepseek-official`/`openai`/`zhipu`/`kimi`/`hunyuan`/`qwen`/`fast`）同样没有账号条目，账号路由即使放行也找不到规则。
- 悬浮卡片概览（`/api/token-monitor/overview`）与用量明细的 provider 过滤是精确匹配：记录存 `deepseek-official` 时，客户端按当前 provider `deepseek-account` 查询会返回 null。
- 官方余额来源与内置脚本/端点判定同样只认 `deepseek-official`。
- 客户端扣费门禁 `hasConfiguredBillingRule` 按精确 provider 匹配已保存规则：账号路由的扣费事件因找不到 `deepseek-account` 条目而被 `continue` 跳过，视觉管线拿不到事件——飘字与鲸鱼娘的受击/扣血动画都不再触发（余额条仍正常，所以现象只表现为「动画不播」）。

## 修复

- `plugins/dsh-token-monitor/src/pricing.ts`：新增 `OFFICIAL_PROVIDER_IDS = ['deepseek-official', 'deepseek-account']`、`isOfficialProvider()` 与 `sameProviderFamily()`；资格门禁改用 `isOfficialProvider`，命中结果携带实际路由 id，`PricingEligibility.provider` 类型放宽为 string。
- `billing.ts`：`isDeepseekBillingModel` 与 `rule.source` 的官方判定改用 `isOfficialProvider`；`defaultBillingRules` 默认增补 `deepseek-account` 模板（与官方同模型同价）；`billUsage` 在已保存快照没有账号条目时回退到官方条目计价。
- `balance-provider.ts` / `balance-config.ts`：官方余额来源判定改用 `isOfficialProvider`，并接受 `settingsNs = llm-deepseek-account`。
- `details.ts` / `detail-query.ts`：悬浮卡片概览与用量明细的 provider 过滤改为 `sameProviderFamily`（空值不过滤、官方族互认）。
- `usage-summary.ts`：概览聚合按官方族过滤，历史 `deepseek-official` 记录在账号路由配置下同样计入。
- `packages/client/ui-token-monitor/src/client/BalanceWidget.tsx`：新增本地 `OFFICIAL_PROVIDER_IDS` 与 `isOfficialRoute()`，`hasConfiguredBillingRule` 在已保存规则缺账号条目时按官方条目回退（与 Host `billUsage` 的回退口径一致），并把原先手写 `'deepseek-official'` 的三处判定（保存后应用快照、扣减本地余额、峰谷标签门禁）统一走 `isOfficialRoute()`。**这一条修掉的就是用户在桌面端反馈的「鲸鱼娘扣血动画与受击效果不能正常播放」**：账号路由的扣费事件此前在客户端被整体丢弃。
- `packages/client/ui-token-monitor/src/client/hostCompatApi.ts`：新增 `SHOW_HOST_COMPAT_HINT` 开关。按 2026-09-29 的决定先不展示「已停止写入会话日志」提示——会话金额已由本地账本统计，界面再报这句话会让使用者误以为功能不可用；宿主补上 `ignorable` 转发后把开关改回 `true` 即恢复，判定逻辑与状态数据都不动。`hostCompatHint` 增加可选 `show` 参数，测试据此继续覆盖文案内容。

- **供应商同族去重（2026-09-30）**：账号路由与官方 API key 路由在界面上原本会各占一行（数据概览的供应商下拉、设置面板的供应商下拉、计费规则编辑器里的两条 DeepSeek）。现在 Host 新增 `displayProviderId()` 把同族统一成 `deepseek-official` 再列表，默认规则里重复播种的 `deepseek-account` 模板已删除（账号定价仍由 `billUsage` 的官方族回退负责），客户端新增共享模块 `providerFamily.ts` 统一判定。
- **浮窗最大化不再被桌面窗口按钮遮挡（2026-09-30）**：最大化矩形此前只做四边等距内缩，浮窗自己的「还原 / 关闭」按钮会落在桌面外壳标题条下面而点不到；现在 `useFloatingWindow` 与右键菜单都改用外壳发布的 `--dsh-frame-top-clearance` 避让。
