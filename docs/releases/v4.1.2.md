# v4.1.2 修掉源地址安装缺 runtime/ 的问题，安装引导收敛到 npm 包

本次发布只修正一条「装得上、但必然加载失败」的安装路径缺陷，不涉及计费、投影、客户端界面与 runtime 载荷内容，其余功能与 4.1.1 一致。

## 问题

`runtime/` 是随包发布的预编译产物，由 `prepack` 阶段的 `scripts/prepare-package-runtime.mjs` 生成，按设计不入库（`.gitignore` 的 `/runtime/`）。README 的安装章节此前给的是：

```powershell
dsh plugin --profile web add github:wssfk12138/dsh-damage-pulse
```

从 git 源安装时，pnpm 不会执行这个打包脚本，而且不会报错：命令 exit 0，装出来的包里就是没有 `runtime/`。插件启动时无条件读 `runtime/manifest.json`，于是只剩一条无法自我定位的报错：

```
failed to apply loader entry dsh-token-monitor (dsh-damage-pulse) Error: ENOENT ... \runtime\manifest.json
```

装了「启动失败隔离」类插件的宿主还会顺手把这一行写进 profile 的 `cordis.patch.yml` 并置 `disabled: true`，故障从「插件报错」变成「插件静默消失」，界面上只表现为插件不存在。

## 复现与对照

在空目录用 pnpm 12.4.1 / Node v24.18.1 / Windows 执行等价的 git 源安装：exit 0、全程没有任何构建脚本日志，安装目录只有 `assets/ docs/ lib/ node_modules/ patches/ cordis.patch.yml LICENSE package.json README.md tsconfig.bundle.json`；与 4.1.1 的 npm 包逐文件比对，差异只有 `runtime/`（97 个文件）与 CRLF 换行。反向对照：npm 包与 GitHub Release 资产里的 `runtime/` 完整可用。

## 修复

- `README.md`：安装章节主推 npm 发布包 `dsh plugin --profile web add dsh-damage-pulse`，说明源地址装法为什么拿不到 payload，并补上被隔离插件写 `disabled: true` 之后的排查方式。
- `plugins/dsh-token-monitor/src/module-bootstrap.ts`：新增 payload 前置检查，在创建任何 profile 状态目录之前确认 `runtime/manifest.json` 存在；缺失时抛出点名修复方式的错误，而不是让 loader 抛裸 `ENOENT`。
- `pnpm-workspace.yaml`：`allowBuilds` 的占位字符串 `esbuild: set this to true or false` 改为 `esbuild: true`。占位值不是合法取值，会让本仓库自身的安装拿不到 esbuild 构建放行。

以上三处来自社区 PR [#23](https://github.com/wssfk12138/dsh-damage-pulse/pull/23)（[@KevinLIN719](https://github.com/KevinLIN719)），已合并且保留原作者署名。PR 里同时新增的 `package.json` `prepare` 脚本未采纳：它会让 git 安装树为了构建先装 87 个 devDependencies（`build-modules.mjs` 依赖 `tsdown`），而 pnpm 10.26+ 对 git 依赖的构建仍需用户按 `<包名>@<git地址>#<commit>` 放行一次，且这一改动没有真实 `github:` 安装产出 payload 的实测证据，代价与收益不成比例。
