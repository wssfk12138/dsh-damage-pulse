# v4.0.11 DSH 0.1.6 Compatibility

This release keeps the existing compatibility path for older DSH hosts and adds
support for the session-list contract shipped by DSH 0.1.6-alpha.2.

## Compatibility change

Older hosts expose the active session through SessionListState.current. DSH
0.1.6-alpha.2 removed that property and marks the main-view session through
session.retainedBy.mainView instead. The balance widget uses the active session to
resolve its effective provider and model before deciding whether official DeepSeek
pricing applies. Reading only current on the new host left that route unresolved and
could hide the balance card even though the Host plugin was still running.

The client now prefers current when an older host provides it and otherwise selects
the session whose retainedBy.mainView count is greater than zero. The local contract
keeps both fields optional, so one bundle supports both host generations.

The package peer ranges now include ^0.1.6-alpha.1 while retaining every previously
supported range. This lets package managers accept DSH 0.1.6-alpha.2 without
dropping compatibility with the rc, Desktop 2.0.4, 0.1.3, or 0.1.5 lines.

## Scope

- host-contracts.ts: model the old and new session-list fields.
- useRouteEligibility.ts: resolve the active session through either contract.
- route-eligibility.client.spec.ts: cover the 0.1.6-alpha.2 main-view path.
- package.json: version 4.0.11 and DSH 0.1.6 peer ranges.
- lib/client.js and source map: rebuilt from the compatible client source.

## Behavior retained

Provider and model eligibility rules are unchanged. Routes using a third-party
provider remain ineligible for official DeepSeek pricing, so the balance card keeps
the existing visibility behavior on those routes. No installed-only UI or private
notification changes are included.
