# v4.1.0 Modular Release

4.1.0 is the first release where the standard package, the module manager, the
editable billing engine and the movable usage windows ship together, so it takes
a minor version instead of a patch number.

## New in 4.1.0

- **Five removable modules.** `pet`, `overview`, `notify`, `billing` and
  `wechat` load from a verified runtime payload. Removing one removes only its
  features: usage capture and the ledger stay permanent, so uninstalling billing
  keeps recording tokens and stops only the pricing.
- **Module manager.** The settings panel checks GitHub releases, reports the
  installed and available versions, and installs an update only after the
  downloaded pack matches the SHA-256 digest published in the release manifest.
  Downloads are limited to the fixed GitHub release hosts, refuse redirects
  outside them and are size-capped.
- **Visual billing-rule editor.** Peak/off-peak windows, per-model price tables
  and third-party provider balance scripts can be edited in the UI. A saved
  adapter is keyless by contract: it names a request and parses a response,
  while the Host keeps the endpoint, the credential and the DNS-pinned
  transport that refuses non-public destinations.
- **Draggable and resizable usage and billing windows.** The usage-details
  window and the billing-rules window share one floating-window implementation
  (`src/client/window-frame.tsx`): title-bar drag, eight-way resize,
  maximize/restore, remembered geometry, and no modal overlay that blocks the
  conversation behind it. The column-setup card is measured before it opens, so
  it never covers its own trigger, and any press outside it closes it even when
  the window itself stopped the press from bubbling.
- **Statutory holidays and rescheduled weekends count as off-peak.** DeepSeek's
  official rule of 2026-09-25 makes a whole statutory holiday and a whole
  rescheduled (make-up) weekend day off-peak for DeepSeek models, official or
  third-party. The rule also applies to past dates, so usage recorded on
  2026-09-25 and later is priced with it. No frontend change is involved.

## Compatibility

The package peers now also accept `^0.1.7-rc.2` while every previously supported
range is retained (`0.1.0-rc.5` onwards, Desktop 2.0.4, the 0.1.5 and 0.1.6
lines), so one tarball covers the newest DSH prerelease and the old hosts. The
client bundle stays single-file: the module loader answers bare module-table rows
and dynamic chunks only, so a synchronously required sibling chunk has no table
entry and fails the whole package.

## Platform-side patches

Two host-side patches accompany this release. `patches/README.md` records the
target versions, the symptoms and the application steps for both.

- `patches/@deepseek-ai__dsh-session@0.1.7-alpha.2.patch` carries `ignorable`
  from `Session.append` into the surface metadata, so the plugin's usage rows can
  be marked droppable. The repository's `patchedDependencies` applies it during
  install.
- `patches/harness/@deepseek-ai__dsh-session-format-v3-to-v4@0.1.7-rc.2.patch`
  repairs the v3 to v4 session migration for logs that were interrupted inside a
  tool call. Without it the migration refuses the transformed artifact and the
  host reports 历史加载失败 with the source log left untouched, so the session cannot
  be opened at all. Official harness drops up to `0.1.7-rc.2` do not contain the
  repair.

## Dead code removed

`balance.ts` and `balance-selection.ts` registered a second
`/api/token-monitor/balance` handler without the Host/Origin guard, resolved the
DeepSeek key themselves and wrote the balance into the host log. Nothing in the
modular build imported them, so the route never came up, but any future import
would have published account balances to every caller that could reach the port.
The live endpoint is the one `balance-api.ts` registers behind
`createRouteGuard`. The unused `tokenMonitorWechat` compatibility facade and its
two focused test files are gone as well; the bundled WeChat routes are the only
path, and `tests/plugin-startup.test.ts` keeps asserting that the plugin exposes
no such service.

## Scope

- `plugins/dsh-token-monitor/src/{update,balance-api,http-trust}.ts`: release
  4.1.0 and the guarded provider-balance surface.
- `patches/**/*`: host-side patches and their index.
- `package.json`: version 4.1.0, DSH 0.1.7-rc.2 peer ranges, patches in `files`.
- `lib/index.js`, `lib/client.js` and the client source map: rebuilt from the
  released source.
- Removals: `src/balance.ts`, `src/balance-selection.ts`, `src/wechat.ts` and
  their focused tests.

- `pnpm run test`: 38 root cases through `node --test` and 81 files / 589 cases

## Behavior retained

Billing eligibility still depends on both provider and model, and the ledger
still records unpriced usage without charging it. Session amounts, the whale-girl
contract, the budget and peak reminders, the WeChat connection routes and the
legacy client bridge are unchanged.
